# RTX 8000 direct PQ2 prefill operator, 2026-10-05

The custom CUTLASS path beat stock Bonsai on both representative PQ2 matrix
products. This is a direct CUDA backend operator result. It does not establish
full-model or long-context prefill throughput.

| Product dimensions (M, N, K) | Custom, µs/run | Bonsai, µs/run | Custom gain |
| --- | ---: | ---: | ---: |
| 17408, 2048, 5120 | 5493.83 | 6242.14 | 12.0% |
| 5120, 2048, 17408 | 5555.73 | 6307.43 | 11.9% |

Both paths ran in the same staged binary on the Quadro RTX 8000 (SM75).
`MERLIN_ENGINE_FORCE_CUSTOM=1` selected the custom kernel. A fresh, unmatched
`MERLIN_ENGINE_PROFILE` selected Bonsai without calibration; each stock kernel
log recorded 167 `prism` dispatches. The `test-backend-ops perf` harness reported
332 custom runs and 166 stock runs per shape. `test-backend-ops test` accepted
both representative products against the CPU reference. An additional odd-tail
product (M=17409, N=2049, K=5120) passed 1/1 with the custom
`pq2_cutlass_128x128x128_s1` kernel selected. No endpoint binary was installed.

The winning source uses a 128×128×128 eight-warp CUTLASS INT8 tile, Bonsai's
PQ2/Q8 scales and quantizer, one aligned 64-bit Q8 payload load per thread,
one aligned 128-bit Q8 scale load, and a column-fastest CTA grid. Alternating
the low/high shared-memory store order by packed-weight row and Q8 column
avoids bank conflicts. The column-fastest grid improved first-shape timing
from 5.733 to 5.625 ms. A plain 64-bit Q8 load regressed to 5.689 ms and
raised measured shared-bank conflicts from 3.38 million to 14.53 million;
the alternating store order brought timing to 5.494 ms. The grid's benefit
from weight cache reuse is an inference from launch order and timing, not a
directly isolated cache-hit measurement.
