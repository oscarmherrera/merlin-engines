# RTX 3090 direct long-context attention, 2026-10-06

The pinned runtime selects an eight-head MMA group for this model's 6:1 grouped-query attention. The isolated SM86 candidate selects the existing two-head group for 256-dimensional prefill queries, leaving decode batches of eight or fewer unchanged. This is the same geometry-specific selection already measured on the RTX 8000. The source change is limited to the attention dispatch condition; the measured mechanism is a different specialization, while the exact hardware-counter cause of its speedup was not isolated.

The direct `test-backend-ops` case used 24 query heads, four KV heads, 256-dimensional Q/K/V, 2,048 queries, and Q8/Q8 KV. The same test executable on `.42` used the stock SM86 library and then the candidate library; `ldd` showed that the candidate run loaded its isolated CUDA library. The production stock endpoint remained resident and unchanged. Robot `running_runs.total` was zero before each GPU test.

| KV depth | Stock Q8 attention | Two-head Q8 attention | Time reduction |
|---:|---:|---:|---:|
| 65,536 | 60.277 ms | 47.940 ms | 20.5% |
| 225,280 | 212.686 ms | 170.617 ms | 19.8% |

At 65,536 KV, F16/F16 measured 59.834 ms stock and 47.554 ms candidate. The candidate passed both Q8 and F16 CPU-reference attention cases at 512 KV tokens and 16 query tokens (2/2). The large performance cases were not CPU-reference checked. Each row is one paired benchmark with internal graph replays, not independent trials or a full-model throughput claim.

The candidate was compiled incrementally from the pinned SM86 scratch build on `.30` by rebuilding only `ggml-cuda` (18 seconds). The prior `fattn.cu` bytes were copied before the trial. Its library was staged separately at `/home/oscar/merlin-attn-sm86-twohead-20261006` on `.42`. Raw stock, candidate, and correctness logs are saved on this Mac at `/Users/oscar/Projects/merlin-engine-measurements/rtx3090-attention-2026-10-06/`.

The engine overlay now includes the measured SM86 dispatch condition. This does **not** establish a 15% time-to-first-token or whole-request improvement: attention's share of a full 3090 prefill has not been traced. With the production endpoint resident, the card had only about 4.8 GiB free, so a second 27B direct model load could not provide a valid full-model trace. No endpoint, fleet config, or SpecKit was changed.
