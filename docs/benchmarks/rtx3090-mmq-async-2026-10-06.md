# RTX 3090 native MMQ prefill follow-up, 2026-10-06

The losing SM86 CUTLASS prefill candidate is not selected by the committed engine. A fresh direct comparison instead exercised Bonsai's native PQ2/Q8 MMQ path, enabling its existing asynchronous Q8 double buffer on SM86. The retained overlay narrows that change to PQ2 on SM86; DGX Spark's existing Q1/Q2/PQ2 behavior remains unchanged. Packed PQ2 weights stay resident, and no model-sized expansion is introduced.

All measurements used the same `test-backend-ops-diag` executable, two 2,048-column model matrix products, a 16-node graph cap, Q8 activation quantization, and no forced custom dispatch. Separate library directories supplied stock, async, and async-plus-packed-weight-prefetch CUDA code. Loader inspection confirmed each selected library. The retained narrow PQ2-only library was compiled from the exact two-source-site overlay and passed both CPU-reference cases (2/2). Its dispatch log selected `prism`, not CUTLASS, for the sampled prefill submissions. Robot `running_runs.total` was zero before each GPU test. The production endpoint stayed stock and unchanged.

These are one paired graph-replay benchmark per variant and shape, not independent run distributions or full-model throughput. The prefetch scratch variant beat the broad async trial by only 0.012/0.010 ms in this fresh pair, an additional 0.3–0.4%; it adds device instructions and is not retained. The earlier `merlin-3090-weight-prefetch-perf.log` contains **forced CUTLASS dispatch** and cannot support a native-MMQ performance claim. The fresh non-forced logs are the evidence for the table.

The retained code has only two changes in pinned `mmq.cuh`: the SM86/PQ2 device-side async buffer condition and the matching host-side shared-memory allocation. The overlay was applied to a clean pinned header, its exact diff was read, and the affected CUDA library compiled successfully. Raw timing, dispatch, and correctness logs are saved on this Mac at `/Users/oscar/Projects/merlin-engine-measurements/rtx3090-mmq-2026-10-06/`.

The prior 10% **matrix-operator** target remains unmet. The measured SM86 two-head attention change is separately about 20% faster on long-context attention, but there is no full-model 3090 prefill or TTFT result combining the two. With the production endpoint resident, only about 4.8 GiB of VRAM was free, insufficient for a second 27B direct model load. No endpoint, fleet config, or SpecKit was changed.
