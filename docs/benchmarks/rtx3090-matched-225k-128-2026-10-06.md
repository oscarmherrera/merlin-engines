# RTX 3090 matched 225K direct model result

The stock and custom runs used the same Bonsai 2 27B PQ2 model, `llama-bench` executable and pinned upstream `adfffbe` common libraries. Only `libggml-cuda.so.0` differed: the stock control loaded `/opt/merlin/lib/prism-b10743-adfffbe/libggml-cuda.so.0.21.0`, and the custom run loaded the clean SM86 runtime built from engine revision `7d47aaa`. `ldd` confirmed both selections. The stock endpoint was temporarily stopped to free its resident VRAM, then restored after the four direct runs; `/state` again reported binding `prism-adfffbe`, endpoint commit `7f4081f1`, zero busy slots and zero in-flight generations.

Both variants used Q8/Q8 KV, batch 4,096, microbatch 2,048, flash attention, and one repetition. The custom runs set `MERLIN_ENGINE_FORCE_CUSTOM=1` so calibration could not select a fallback for an eligible custom matrix path.

| Direct measurement | Stock Bonsai | Clean custom engine | Time reduction |
|---|---:|---:|---:|
| 225,000 prompt tokens plus 128 generated tokens (`-pg 225000,128`) | 340.215 s | 295.605 s | **13.1%** |
| Timed 128-token decode after a 225K cache fill (`-d 225000 -n 128`) | 6.239 s | 4.842 s | **22.4%** |

The depth test fills the cache outside its timed generation row. Its generation rates were 20.517 and 26.435 tokens/s, respectively. These are one matched run per variant, not repeated-run distributions. The prompt-plus-generation timer does not isolate prefill time or endpoint time-to-first-token; `llama-bench` does not compare generated text.

The custom prompt-plus-generation dispatch log recorded 342 Bonsai/Prism prefill matrix selections (`unsupported_prefill_shape_or_layout`) and 259 custom `pq2_q8_1_dp4a_warp` decode matrix selections (`forced_diagnostic`). The custom depth log recorded 299 and 257, respectively. These are selection events, not counts of CUDA graph replays or a per-operation timing profile. The SM86 PQ2 asynchronous MMQ change operates inside the Bonsai prefill path, and the grouped attention path is validated separately by the clean-library 225K attention operator and CPU-reference tests. This direct run does not isolate how much of the end-to-end gain came from each component.
