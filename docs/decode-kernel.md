# Packed PQ2 decode prototype

Status (2026-10-04): the Q8 revision compiled for `sm_75` and passed the existing direct RTX8000 CUDA backend runner (17/17 graph cases, including numerical references). At `M=17408, K=5120`, batches 1/2/4/8 were 2.59–5.91 times slower than Prism despite a 15–19% gain over the earlier custom F32 path. Full-model logits, large-context speed and viability remain unverified. The endpoint is back on stock Bonsai; further engine tests are direct runs until the owner changes that instruction. No SpecKit work is included.

`merlin_pq2_decode<batch, gated>` specializes batches 1, 2, 4 and 8. One warp computes one output row; four warps form a block. Each lane processes complete 32-value Q8_1 groups from the existing Prism activation buffer. It decodes all four PQ2 codes (-1, 0, +1, +2), accumulates an integer dot product, then applies the original weight and activation half scales in F32. Weights stay packed in VRAM. Workspace is the reused Q8 buffer: batch times padded K divided by 32 times `sizeof(block_q8_1)`.

Symbol accumulation selects integer `-a`, `0`, `a`, or `a+a`; scaling occurs once per 32-value dot, matching Prism's quantization boundaries. The same arithmetic serves main and gate weights. Float reduction order still differs from Prism. This implements the design's packed add/subtract experiment; it does not establish a performance win. Numerical validation includes explicit packed codes 0/1/2/3, alternating block scales and deterministic activation/bias inputs because the normal random PQ2 quantizer never produces code 3 (+2).

The existing `ggml_cuda_mul_mat_vec_q` production entry point calls the custom dispatcher after validating fusion arguments, clearing padding and allocating the existing Q8 activation buffer. Native and reference callbacks each invoke the original quantizer once, inside their timed work; matrix candidates invoke their own original MMQ quantizer instead. Ordinary matrix multiplication and graph-fused MMVQ calls share this hook. Existing Hadamard graph operations and the earlier FWHT dispatch remain in place.

The supported domain is Turing compute capability 7.5 (`cc == 750`), PQ2_0 weights, F32 activations/output, contiguous two-dimensional tensors on this CUDA device, positive dimensions, K divisible by 128, and N in {1,2,4,8}. Output must not overlap input weights or activations. Batch-1 bias and gate fusions use the existing SiLU, GELU and SwiGLU-OAI device functions and the same epilogue ordering as Prism. Fused gate matrices must match the weight shape, and bias tensors must be contiguous F32 vectors of M elements. Scale fusion is excluded: upstream permits it only for NVFP4, not PQ2.

Other hardware, formats, broadcasted/permuted tensors, split-device tensors and expert-indexed `MUL_MAT_ID` remain separate existing dispatcher domains. This prototype does not implement PTQ1 or AMD kernels. Eligible decode shapes register native decode and, when unfused and compatible, both CUTLASS matrix tiles. Normal inference selects only numerically accepted, faster candidates from a matching startup profile; otherwise it uses Prism. See [measured dispatch](measured-dispatch.md) for the calibration and graph boundaries.

Dispatch telemetry identifies native work as `pq2_q8_1_addsub_warp`, records the Q8 workspace bytes and preserves the actual workload phase, batch and token metadata. Host submissions remain distinct from GPU completion receipts and graph replay completion. A host dispatch log alone does not prove executed GPU work.

The source integration check applies `scripts/apply_runtime.py` to a clean pinned checkout and inspects the central hook. The completed RTX8000 17-case direct backend run established compilation, candidate execution and numerical acceptance for its covered graph shapes. It does not replace full-model logits, fused bias/gate coverage beyond those cases, sustained decode or large-context tests. The pinned backend test's PQ2 NMSE bound is 5e-4. See the [measured cases](benchmarks/rtx8000-13288e4-kernel-diagnosis.md).
